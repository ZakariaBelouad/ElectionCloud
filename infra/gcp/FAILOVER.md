# Manual failover and failback

1. Confirm the election ID, approved close and drained outbox with Person 1. Record authoritative final turnout. Stop if the election is open or the data owners cannot verify that the input is complete.
2. Confirm the primary tally failure with Person 2 and operations. Check whether a canonical result already exists and record its ETag if present. Assign one standby operator and record authorization in the incident log. Pause primary publishing during the handoff.
3. Connect to the standby with OS Login, confirm the current commit matches the EC2 release SHA, and confirm the checkout is clean. Follow the [primary tally key and Cosmos procedure](../aws/RUNBOOK.md#primary-tally-host) with the standby operator's own authorized identity. Run turnout first and require both closed status and authoritative final turnout. Retrieve the approved Azure Key Vault version only after authorization, using restricted temporary RAM storage.
4. Run the same `infra/aws/tally_result.py` command using the same election partition and protected output procedure as EC2. Confirm the result's election ID and schema version, exact candidate names, nonnegative integer counts and total equal to final turnout. Compare every count with an independently approved primary aggregate whenever available. Use the AWS synthetic fixture for the local demo. If the primary failed before producing an aggregate, have the designated reviewer verify closure, release, turnout and the computed aggregate before approving publication. Hold on any discrepancy.
5. Publish only through Person 1's approved path. The proposed interface is the [AWS conditional Azure Blob create](../aws/RUNBOOK.md#primary-tally-host) against the same private container and canonical election object from either host. If the canonical result exists, read and compare it. Record an exact match as already published and escalate a mismatch. After a timeout, read before retrying. Record the canonical path and ETag, operator authorization, commit, UTC times and duration.
6. When primary is healthy, verify its connectivity and revision and reconcile its view with the canonical result. Return operator ownership to EC2 with Person 2 and record the handoff. Keep the election closed and the accepted result in place. Clean the key material from the standby session, sign out and revoke temporary access.
